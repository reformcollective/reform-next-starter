Date of research: 2026-10-27. Method: WebFetch/WebSearch against primary sources plus the local Next docs in node_modules. Rule applied: a fact is stated only if a fetched primary source said it; otherwise "NOT VERIFIED".

Caveats on tooling (read these first):

- The fetch tool summarizes pages with a small model and clips quotes to about 125 characters. Quotes below are therefore often the opening clause of a rule, not the whole sentence. Where the full text mattered I say "(clipped)".
- Provider columns: F = native file or HLS via hls.js, Mx = Mux, YT = YouTube, Vi = Vimeo, Wi = Wistia, CF = Cloudflare Stream, Tw = Twitch, Tk = TikTok, Sp = Spotify. "NV" = NOT VERIFIED for that provider. Only providers with a source are listed; all unlisted providers are NV.
- Value / Effort / Risk columns are YOUR JUDGMENT (the author's, not sourced facts). Everything else in the table is sourced in the notes below.
- Several Mux, Vimeo, Wistia and Video.js pages were only read through summaries; the sources that failed (404 or empty) are listed at the end.

## 2. Detailed notes

### A. Playback

**A1 Start/end/clip (media fragments).**

- W3C Media Fragments: "Temporal clipping is denoted by the name `t`, and specified as an interval with a begin time and an end time" (4.2.1). Begin time is inclusive, a missing begin defaults to 0, a missing end defaults to duration. "Invalid temporal fragments SHOULD be ignored by the user agent." Beyond media length the UA "seeks to the end of the media". Source: https://www.w3.org/TR/media-frags/
- Google caveat for indexing: "Don't use fragment identifiers to load the video, as Google Search doesn't generally support URL fragments." https://developers.google.com/search/docs/appearance/video (so do not rely on `#t=` for the indexable content URL; use it on the playback element only).
- YouTube: start = "causes the player to begin playing the video at the given number of seconds from the start of the video"; end is measured "from the start of the video", not from `start`. https://developers.google.com/youtube/player_parameters . `loadVideoById` object syntax accepts `startSeconds`/`endSeconds`; argument syntax does not support `endSeconds`. https://developers.google.com/youtube/iframe_api_reference
- Mux: `start-time` (seconds, default 0) and when set it is also used for `thumbnail-time` if none given; `thumbnail-time` is unavailable with signed URLs (signed setups put `time` in the token). Search summary of https://www.mux.com/docs/guides/player-api-reference/html and https://www.mux.com/docs/guides/set-a-default-thumbnail (second page appeared in results, not fetched).
- Cloudflare: `startTime` as seconds (`123`) or `1h12m27s`. https://developers.cloudflare.com/stream/viewing-videos/using-the-stream-player/
- Twitch: `time` in `1h2m3s` format (VOD only for JS embed). https://dev.twitch.tv/docs/embed/video-and-clips/
- Spotify: `loadEntity(spotifyUriOrUrl, preferVideo, startAt)` and `seek(seconds)`. https://developer.spotify.com/documentation/embeds/references/iframe-api
- Wistia: `time(val)` method. https://docs.wistia.com/docs/javascript-player-api
- Vimeo: the embed options page summary lists "start time via `#t=`" but gave no syntax; NOT VERIFIED beyond that. https://developer.vimeo.com/player/sdk/embed
- TikTok: NOT VERIFIED.

**A2 Loop.** YouTube: single-video loop needs `playlist` set to own ID ("IFrame support is limited"). `setLoop(loopPlaylists)` is for playlists. Vimeo has `setLoop`/`getLoop`. Mux `loop` attribute. Cloudflare `loop` (default false). Sources above. Loop range: NOT VERIFIED in any provider doc read; implement via timeupdate/seek.

**A3 Playback rate.** YouTube: "Calling this function does not guarantee that the playback rate will actually change"; listen to `onPlaybackRateChange`; `getAvailablePlaybackRates`. Wistia `playbackRate(r)`. Vimeo `setPlaybackRate` and `playbackratechange` event (names only, from the player.js README: https://github.com/vimeo/player.js/blob/master/README.md). Mux `playbackrate`, `playbackrates`. Twitch and TikTok: NV. Spotify: NV.

**A4 Autoplay policy.** MDN https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay: "you can assume that media will be allowed to autoplay only if at least one of the following is true: The audio is muted or its volume is set to 0" or user has interacted. `play()` "is rejected when playback fails to begin (such as if autoplay is denied)"; `NotAllowedError` signals permission issue. `playsinline` "is required for autoplay in Safari". Default `autoplay` Permissions Policy is `self`; iframes need `allow="autoplay"`. MDN video page: "To disable video autoplay, `autoplay="false"` will not work"; `loading="lazy"` on video defers download and autoplay until near viewport. https://developer.mozilla.org/en-US/docs/Web/HTML/Element/video . Mux `autoplay` accepts boolean, `"muted"`, `"any"` (retries muted if needed). Cloudflare: "Mobile browsers generally ignore" autoplay. Twitch autoplay defaults true, mobile needs interaction. YouTube required minimum functionality: autoplay should wait until "more than half of the player is visible", and "A page can't run more than one auto-playing YouTube player at the same time." https://developers.google.com/youtube/terms/required-minimum-functionality (the second is the sourced basis for concurrency limits for YT only).

**A5 Sources and codec fallback.** MDN: browser tries each `<source>` in order, `error` fires on the video after all fail; `type` may include `codecs`. WHATWG: `type` helps "determine if it can play this media resource before fetching it". https://html.spec.whatwg.org/multipage/embedded-content.html#the-source-element

**A6 Art direction.** WHATWG: for `<source media>` under video/audio, "only evaluated once during the resource selection algorithm", unlike `picture`. So breakpoint-specific sources will not respond to resize; a component must re-select on resize in JS (design inference, flagged). Same URL as A5.

**A7 prefers-reduced-data.** MDN: "The `prefers-reduced-data` CSS media feature is used to detect if the user has requested web content that consumes less internet traffic." Values `no-preference`, `reduce`. "This feature is not Baseline", "experimental". The fetched page also contained a contradictory warning "not supported by any user agent"; per-browser table not seen. https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-data . Treat as progressive enhancement only.

**A8 Reduced motion.** MDN: detects "whether a user has asked their device to minimize non-essential motion"; Baseline widely available since January 2020. https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion . WCAG does not itself say reduced-motion must stop video; the WCAG obligation is 2.2.2 (below).

**A9 Live.** hls.js (https://raw.githubusercontent.com/video-dev/hls.js/master/docs/API.md): `lowLatencyMode` default true; `liveSyncDurationCount` default 3; `Hls.isSupported()` checks MSE; error types NETWORK_ERROR, MEDIA_ERROR, KEY_SYSTEM_ERROR, MUX_ERROR, OTHER_ERROR with `fatal` flag; `destroy()` to free resources. Mux: live "non-DVR mode (live edge only) or DVR mode (backward seeking)"; `stream-type` on-demand/live/DVR variants; `target-live-window` ("`Infinity` means full DVR"); default Cast receiver "doesn't support low-latency live streams". https://www.mux.com/docs/guides/mux-player-web and player API reference. Cloudflare: "Low-Latency HLS playback is in beta". YouTube `getDuration` for live "returns the time the stream has been running". Twitch events `OFFLINE`/`ONLINE`.

**A10 DRM.** Mux: "Google Widevine, Microsoft PlayReady, and Apple FairPlay"; "DRM requires the use of Signed URLs"; needs playback token plus DRM license token (`drm-token`); video quality `plus` or `premium`; "Only video tracks are protected, so audio-only assets and live streams aren't covered." https://www.mux.com/docs/guides/protect-videos-with-drm . hls.js ERROR types include KEY_SYSTEM_ERROR. Recommendation (judgment): out of scope for v1; expose a `drmToken` passthrough at most. Other providers: NV.

**A11 PiP.** MDN: "enables websites to create a floating, always-on-top video window"; not Baseline; `disablePictureInPicture` is "a hint"; `requestPictureInPicture()` on `<video>`; Document PiP extends to arbitrary HTML. https://developer.mozilla.org/en-US/docs/Web/API/Picture-in-Picture_API . User-gesture requirement: NOT VERIFIED on MDN page (example uses click). Vimeo: `requestPictureInPicture`, `enterpictureinpicture` events (README). YouTube iframe: NV.

**A12 AirPlay / Cast.** W3C Remote Playback: `prompt()` rejects with `InvalidAccessError` without transient activation; states `connecting`, `connected`, `disconnected`; `disableRemotePlayback` attribute means UA must not play remotely or show UI. https://www.w3.org/TR/remote-playback/ . MDN: "not Baseline"; `watchAvailability()`. Mux Player: "Casting is built in. Versions before 2.3.0 need the Google Cast script." Media Chrome ships airplay and cast buttons (https://www.media-chrome.org/docs/en/get-started). Video.js 10 overview lists `google-cast` extension and `media-cast-button`. Vimeo SDK lists `remotePlaybackPrompt` and related events.

**A13 Sticky / lightbox.** No standard. Sourced constraint: YouTube "You must not display overlays, frames, or other visual elements in front of any part of a YouTube embedded player"; minimum 200x200 viewport; a thumbnail that starts playback must be at least 120 by 70. https://developers.google.com/youtube/terms/required-minimum-functionality . Implication (judgment): a mini-player must move the iframe, not draw over it; facade placeholders are not directly addressed by the doc.

**A14 Keyboard / double-tap.** YouTube `disablekb`; Mux `hotkeys`, `nohotkeys`, `forward-seek-offset`/`backward-seek-offset` default 10. Mux player supports keyboard navigation and screen readers. Double-tap: NOT VERIFIED in any source read.

**A15 Scrub thumbnails.** Mux: "A storyboard is a collection of thumbnails or tiles, created from video frames selected at regular time intervals." URLs `https://image.mux.com/{PLAYBACK_ID}/storyboard.{png|jpg|webp}`, `storyboard.vtt` (cues use `#xywh=`), `storyboard.json`; tile example 256x160; 50 tiles under 15 minutes, 100 longer. https://www.mux.com/docs/guides/create-timeline-hover-previews . Signed: storyboard token `aud: s`. Mux Player: "timeline hover previews" automatic for Mux-hosted. Other providers: NV.

**A16 Chapters.** MDN `track kind="chapters"`: "Chapter titles are intended to be used when the user is navigating the media resource." WebVTT: "Chapters are plain text, typically just a single line." https://www.w3.org/TR/webvtt1/ . Mux `addChapters([{startTime, endTime?, value}])`, `chapterchange` event, VOD and audio only, not live; removed when playback ID changes (from search summary of https://www.mux.com/docs/guides/player-advanced-usage; one Mux example used `title` instead of `value`, the API reference is authoritative). Vimeo `getChapters`, `getCurrentChapter`, `chapterchange`. Wistia: no chapter method; use `time(val)`.

**A17 Audio tracks / AD.** Mux: alternate tracks "other languages, audio descriptions, or commentary"; added via asset tracks endpoint with BCP-47 `language_code`; "Mux will automatically add it to the HLS playback URL". Player shows audio track selector "when a stream has multiple audio tracks" (`--audio-track-menu-button` hides). https://www.mux.com/docs/guides/add-alternate-audio-tracks-to-your-videos . hls.js `audioTracks`/`audioTrack`. Vimeo `getAudioTracks`, `selectAudioTrack`. Text descriptions: `kind="descriptions"` "intended to be synthesized as audio when the visual component is obscured". https://developer.mozilla.org/en-US/docs/Web/HTML/Element/track

**A18 Captions.** Track kinds (MDN): subtitles, captions, descriptions, chapters, metadata; default kind is subtitles; invalid becomes metadata. Mux: SRT/WebVTT at creation or via create-track; `closed_captions: true`; SDH flag; `default_subtitles_lang` query param on HLS URL; auto-generated captions available. https://www.mux.com/docs/guides/add-subtitles-to-your-videos . YouTube: `cc_load_policy=1` shows captions by default; `cc_lang_pref`; `hl`; captions module `fontSize` -1 to 3. Cloudflare `defaultTextTrack` (init only). Vimeo `texttrack` option, `enableTextTrack`. Wistia: `captionschange` event; `plugin('captions')`.

**A19 `::cue`.** MDN: "Rules whose selectors include this element may only use the following CSS properties": background family, color, font family, line-height, opacity, outline, ruby-position, text-combine-upright, text-decoration, text-shadow, visibility, white-space. https://developer.mozilla.org/en-US/docs/Web/CSS/::cue . Applies to native `<track>` rendering only; custom caption rendering would be needed for full control (judgment). `::cue-region` rules NOT VERIFIED (truncated).

**A20 Transcript / sign language.** No player API sourced. WCAG: 1.2.6 sign language (AAA); media alternative defined (below). Mux can auto-generate captions and "use transcripts" (guide title: https://www.mux.com/docs/guides/add-autogenerated-captions-and-use-transcripts, search result only).

### C. SEO and structured data

All quotes https://developers.google.com/search/docs/appearance/structured-data/video unless noted.

- Required VideoObject: `name` ("Make sure to use unique text in the `name` property for each video on your site."), `thumbnailUrl` ("A URL pointing to the video's unique thumbnail image file."), `uploadDate` (ISO 8601).
- Recommended: `contentUrl` ("We recommend that your provide the `contentUrl` property, if possible."), `embedUrl` ("If `contentUrl` isn't available, provide `embedUrl` as an alternative."), `description`, `duration`, `expires`, `hasPart` (Clip), `ineligibleRegion`, `regionsAllowed`, `interactionStatistic`, `publication` (for LIVE), `creator/author`.
- LIVE badge: `publication` with `isLiveBroadcast`, `startDate`, and `endDate` ("It's required to provide the `endDate` once the video has finished and is no longer live."). "The Indexing API only supports livestream videos."
- Clip: required `name`, `startOffset`, `url` ("must point to the same URL path as the video with additional query parameters that specify the time."); `endOffset` recommended. "Make sure that no two clips ... share a start time." SeekToAction: needs deep-link ability and "Google must be able to fetch your video content files."
- Placement: "`VideoObject` structured data must be added to a page where users can watch the video." Eligibility: follow Search Essentials, general structured data guidelines and "video indexing requirements." Clip/SeekToAction note: "The total video duration must be a minimum of 30 seconds."
- Indexing requirements (https://developers.google.com/search/docs/appearance/video): "The watch page must be indexed."; "The video must be embedded on a watch page."; "The video can't be hidden behind other elements."; "The video must have a valid thumbnail that's available at a stable URL."; "The indexed watch page must be performing well in Search before its video can be considered for indexing."; "Data URLs aren't supported."; "A watch page's main purpose is to show users a single video."; "Don't rely on user actions (such as swiping, clicking, or typing) to load the video."; for JS-injected video keep the container "even if the media API call fails"; thumbnail "must be accessible by Googlebot and Googlebot Images". Supported file types listed (MP4, WebM, MOV per summary; full list not seen). ### D. Analytics and consent

- GA4 enhanced measurement (https://support.google.com/analytics/answer/9216061): events `video_start` ("when the video starts playing"), `video_progress` ("when the video progresses past 10%, 25%, 50%, and 75% duration time"), `video_complete` ("when the video ends"). Provider: "For YouTube embedded videos that have JS API support enabled". Parameters: `video_current_time`, `video_duration`, `video_percent`, `video_provider`, `video_title`, `video_url`, `visible`. So it covers only embedded YouTube; for Vimeo, Mux, file etc. you must send these events yourself (consequence). Whether `video_*` appear on the recommended-events page: NOT VERIFIED (page truncated).
- Note the GA4 thresholds are 10/25/50/75 and `video_complete`; the 90 percent threshold in the request is not in GA4's built-in set (NOT VERIFIED as a GA standard).
- GTM YouTube Video trigger (https://support.google.com/tagmanager/answer/7679325): captures Start, Complete, Pause, Seeking, Buffering, Progress; percentages "as a comma separated list of one or more integers"; thresholds fire only the first time reached ("Skipping past a threshold by seeking doesn't fire it" per summary); needs built-in video variables enabled and pushes video data to the data layer; "enablejsapi parameter is appended" when Add JavaScript API support is checked, which can reload a playing video.
- Data layer pattern (GTM page above): video interaction data is pushed to the data layer. A cross-provider documented standard: NOT VERIFIED. Design suggestion (judgment): normalize provider events to GA4 names and fields and push to `dataLayer`.
- Mux Data: Mux Player sends metrics automatically, `env-key` override, `metadata-video-title`, `metadata-viewer-user-id`, `disable-tracking`, `disable-cookies` (must be set before playback-id, per search summary). Events: `play`, `pause`, `ended`, `timeupdate` at least every 250 ms; views end after 60 seconds without events; custom integrations emit via `mux.emit(playerId, 'play')`. https://docs.mux.com/guides/mux-data-playback-events , https://www.mux.com/docs/guides/data-engagement-metric (search results). No Mux-defined 10/25/50/75/90 progress events found.
- Provider event surfaces for adapters: YouTube `onStateChange` (-1, 0, 1, 2, 3, 5), `getCurrentTime`, `getDuration`; Vimeo events play/pause/ended/timeupdate/progress/seeked/error; Wistia `play`, `pause`, `end`, `percentwatchedchanged`, `timechange`; Twitch `PLAY`, `PAUSE`, `ENDED`, `READY`, `OFFLINE`, `ONLINE`; Spotify `ready`, `playback_started`, `playback_update` (position and duration in ms); Cloudflare: no event API documented on the player page; TikTok: no events documented on the page read.
- Privacy parameters:
  - YouTube (https://support.google.com/youtube/answer/171780): views in this mode "will not be used to personalize the YouTube browsing experience"; "Change the domain for the embed URL in your HTML from https://www.youtube.com to https://www.youtube-nocookie.com."; "Privacy Enhanced Mode is available only for embedded players on websites."; child-directed sites still must self-designate.   - Vimeo (https://help.vimeo.com/hc/en-us/articles/12426260232977-About-Do-Not-Track-and-Vimeo-embeds): `dnt` "blocks the player from collecting session data and analytics" but "some essential cookies will still be active." Cookie list lives on a separate Vimeo page not fetched; a third party quoted player_clearance, cf_clearance, _cf_bm, _cfuvid (not primary).
  - Therefore (judgment): neither parameter equals consent; the facade must not load the iframe before consent when consent is required. Whether this satisfies GDPR: NOT VERIFIED (legal question, no primary source consulted).
- Facade-as-consent: web.dev describes the facade as click-to-load ("When the user interacts with the static placeholder ... the third-party embed is loaded"); linking this to consent is an application of it, not a sourced rule.

### F. Authoring and platform

- Stega (https://www.sanity.io/docs/visual-editing/visual-editing-client-stega): "Stega encoding embeds Content Source Map data as invisible characters appended to string values." Default filter skips dates, URLs, slugs, internal keys, ID-like fields, SEO and metadata paths, type paths and a denylist of 39 field names. "Stega-encoded strings contain invisible characters that can break non-display operations like string comparisons" (also URL construction, date parsing, length checks). "`stegaClean()` performs a deep clean: it serializes the value to JSON, strips all invisible character sequences" and works on strings, objects, arrays. Custom `filter(value, paths, source, defaultFilter)` can return true/false per value. Consequence (judgment): provider enum fields, provider IDs, URLs, start/end times as strings and booleans-as-strings in a video object will be encoded unless clean; call `stegaClean()` on the whole video object before parsing, and treat provider switching on the cleaned value. A URL field is skipped by the default filter, but a provider ID or text field is not.
